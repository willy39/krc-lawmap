## 0. 한 줄 요약

국가법령정보센터(law.go.kr)에 흩어진 대한적십자사 관련 자료를 **두 개의 축**으로 정리해 한 화면에서 보고, 클릭 한 번으로 원문에 닿게 하는 정적 웹서비스.

- **규범 축 (법규 나무)**: 헌법·조약 → 법률·시행령 → 행정규칙 → **자치법규(조례·규칙)** → 정관 → 규정 → 시행규칙
- **해석·적용 축 (판례·해석 라이브러리)**: **판례 · 헌재결정례 · 법령해석례 · 중앙부처 1차 해석 · 중앙행정기관 결정선례 · 행정심판례**
- **연결**: 규범 항목마다 "이 규범을 다룬 판례·해석", 판례·해석마다 "관련 규범"을 서로 연결

## 1. 배경 및 목표

### 1.1 문제
- 대한적십자사의 법규는 **법령**, **기관 내부규정(정관·규정·시행규칙)**, **지자체 조례(적십자 지원·헌혈 장려 등)** 로 나뉘어 law.go.kr의 서로 다른 메뉴에 흩어져 있다.
- 실무에서 규범의 의미를 확정하는 **판례·유권해석·결정례**는 또 다른 메뉴에 있어, "이 규정과 관련된 판단이 있었나?"를 확인하려면 여러 번 따로 검색해야 한다.

### 1.2 목표 (시범서비스 범위)
| # | 목표 | 성공 기준 |
|---|------|-----------|
| G1 | 대한적십자사 **기관규정 전수 일람** | law.go.kr 공공기관 규정 중 대한적십자사 소관 건수 = 서비스 표시 건수 |
| G2 | **관련 조례 일람** | 17개 시·도와 시·군·구의 적십자·헌혈 관련 조례를 지역별로 조회 |
| G3 | **판례·해석 라이브러리** | 검수를 통과한 관련 판례·해석·결정례를 유형·연도·쟁점별로 조회 |
| G4 | **규범 ↔ 해석 연결** | 핵심 규범(조직법·시행령·정관·혈액관리법 등)에서 관련 판례·해석으로 1클릭 이동 |
| G5 | **원문 링크 무결성** | 모든 항목에 law.go.kr 원문 링크, 깨진 링크 0건 |
| G6 | **최신성** | 기준일·최근 개정·신규 판례 배지, 주 1회 자동 갱신 |
| G7 | 모바일 사용성 | 360px 폭에서 가로 스크롤 없이 일람·트리·라이브러리 이용 |

### 1.3 비목표 (Out of scope, v1)
- 판결문·해석문 **전문 저장·전문검색** (요지와 메타데이터만 저장하고 본문은 원문 링크로 연결)
- 판례의 법리 요약 자동생성(AI 요약), 판례 유효성(변경·폐기) 자동판정
- 로그인·개인화·편집 기능, 법률 해석·자문 제공

## 2. 레퍼런스 분석 — ggc-lawtree

| 요소 | 레퍼런스 구현 | 본 서비스 적용 |
|------|---------------|----------------|
| 메타포 | 뿌리(헌법) → 두 기둥(지방자치법·그 외 국가법령) → 큰가지(업무분야) → 열매(세부분야, 클릭 시 자치법규 펼침) | 뿌리(헌법·제네바협약) → 줄기(조직법) → 큰가지(업무분야) → 열매(규정 묶음). **자치법규는 별도 "곁가지"** 로, **판례·해석은 나무 옆 "도서관"** 으로 분리 |
| 원칙 | 모든 라벨이 원문 링크 | 동일 |
| 범례 | 법률·대통령령·부령·행정규칙 / 조례·규칙·훈령·예규 | 법령계열 / 자치법규계열 / 기관규정계열 / 해석·적용계열 4계열 색상 |
| 보조뷰 | 전체 법규 일람 | 일람 + 지역뷰 + 라이브러리 |
| 신뢰성 | 출처·기준일·건수 내역 | 헤더에 기준일·축별 건수, 푸터에 출처·면책 |

**설계 판단**: 판례·해석을 나무 노드로 넣으면 수백 건이 붙어 조감도가 무너진다. 그래서 나무에는 **노드별 배지(⚖ 3)** 로만 표시하고, 실제 목록은 **라이브러리 화면과 상세 패널**에서 보여준다.

## 3. 콘텐츠 범위

### 3.1 규범 축 — 위계 레벨
| Level | 구분 | 예 | API target |
|-------|------|----|------------|
| L0 | 헌법 | 대한민국헌법 | `law` |
| L0′ | 조약 | 제네바협약(4개)·추가의정서 | `trty` ⚠️ |
| L1 | 근거 법률 | **대한적십자사 조직법** | `law` |
| L2 | 하위 법령 | 대한적십자사 조직법 시행령 | `law` |
| L1r | 관련 법률·하위법령 | 혈액관리법, 재해구호법, 공공기관의 운영에 관한 법률 등 (큐레이션 목록) | `law` |
| L1a | 관련 행정규칙 | 보건복지부 등 소관 고시·훈령 중 적십자 관련 | `admrul` |
| **LO** | **자치법규** | ○○시 적십자사 지원 조례, ○○도 헌혈 장려 조례, 시행규칙 | **`ordin`** |
| L3 | 정관 | 대한적십자사 정관 | `pi` |
| L4 | 규정 | 인사규정, 회계규정, 감사규정 … | `pi` |
| L5 | 시행규칙·세칙 | ○○규정 시행규칙 | `pi` |
| L6 | 지침·요령 | (law.go.kr 등재분) | `pi` |

> 구체 명칭은 **수집 결과로 확정**한다. 설계서에는 구조만 정의한다.

### 3.2 자치법규(조례) 수집 범위
| 묶음 | 검색어(자치법규명 기준) | 상위 연결 대상(부모) |
|------|-------------------------|----------------------|
| 적십자 지원 | `적십자` | 대한적십자사 조직법 |
| 헌혈 장려·지원 | `헌혈` | 혈액관리법 |
| 재난구호 연계 | `재해구호`, `이재민` (+ 본문 `적십자` 포함 여부 확인) | 재해구호법 |
| 이산가족·남북 | `이산가족` | 관련 법률(큐레이션) |
| 기타 | 본문 검색 `대한적십자사` | 수동 지정 |

- 지역 메타데이터: 시·도 / 시·군·구 / 교육청 구분을 저장해 **지역뷰**(7.4)에 사용.
- 1차 묶음(적십자·헌혈)만 기본 포함, 재난구호·이산가족 묶음은 **본문에 '적십자'가 있는 경우만** 포함(과다 수집 방지).
- 보조 수단: 법령–자치법규 연계 API(`lnkOrd` 등)로 조직법·혈액관리법에 연계된 조례 교차확인. 참고 구현 보고에 따르면 커버리지가 낮으므로 **보조 신호로만** 사용.

### 3.4 해석·적용 자료의 관련성 기준
판례·해석은 "대한적십자사 소관"이라는 필터가 없다. 그래서 **검색 → 점수화 → 사람 검수** 3단계로 수집한다.

**① 후보 수집 질의**
| 질의 종류 | 예 | 대상 |
|-----------|----|------|
| 기관명 | `대한적십자사`, `적십자사`, `적십자병원`, `혈액원` | PREC(본문), EXPC, CGM, PRE, DECC |
| 근거법령명 | `대한적십자사 조직법`, `혈액관리법` | 전 유형 (참조조문 필드 우선) |
| 조문 인용 | 「대한적십자사 조직법」 제○조 | PREC·EXPC의 참조조문 파싱 |
| 큐레이션 | 담당자가 지정한 사건번호·안건번호 | 전 유형 |

**② 관련성 점수 (0–100)** — 규칙 기반, `data/relevance.yaml`에서 가중치 조정
| 신호 | 점수 |
|------|------|
| 참조조문에 조직법·시행령 포함 | +50 |
| 사건명·안건명에 기관명 포함 | +40 |
| 당사자·질의기관이 대한적십자사 | +40 |
| 참조조문에 큐레이션 관련 법률(혈액관리법 등) 포함 | +25 |
| 본문에만 기관명 1회 등장 | +10 |
| 상한 | 100 |

**③ 검수 상태**
| 상태 | 의미 | 서비스 노출 |
|------|------|-------------|
| `auto` | 점수 ≥ 70 | 노출 ("자동분류" 표시) |
| `candidate` | 점수 40–69 | 비노출, 검수 대기열 |
| `approved` | 담당자 승인 | 노출 |
| `rejected` | 담당자 제외 | 비노출(재수집 시에도 제외 유지) |

검수는 `data/review.yaml`(사건번호/ID → 상태·쟁점태그·연결규범)을 사람이 편집해 PR로 반영한다. 별도 관리자 화면은 v1에서 만들지 않는다.

## 4. 데이터 수집 설계

### 4.1 법제처 국가법령정보 공동활용 Open API
- 신청: <https://open.law.go.kr> → 회원가입 → Open API 사용 신청 → **인증키(OC)** 발급. 사용 신청 시 **판례·해석례·자치법규·중앙부처 해석 서비스를 모두 체크**.
- 목록: `https://www.law.go.kr/DRF/lawSearch.do?OC={OC}&target={target}&type=XML|JSON&query=...&display=100&page=n`
- 본문: `https://www.law.go.kr/DRF/lawService.do?OC={OC}&target={target}&type=XML|JSON&ID=...`

| 축 | 데이터 | target | 수집 단위 | 저장 범위 |
|----|--------|--------|-----------|-----------|
| 규범 | 현행법령 | `law` | 큐레이션 목록 | 메타 + 목차(조문 제목) |
| 규범 | 시행예정 법령 | `eflaw` | 위와 동일 | 시행예정 플래그 |
| 규범 | 행정규칙 | `admrul` | 키워드 + 선별 | 메타 |
| 규범 | **자치법규** | **`ordin`** | 3.2 검색어 | 메타 + 제1조(목적) |
| 규범 | 조약 | `trty` ⚠️ | 큐레이션 | 메타 |
| 규범 | **공공기관 규정** | **`pi`** | 기관명 필터 | 메타 |
| 해석 | **판례** | **`prec`** | 3.4 질의 | 메타 + 판시사항·판결요지·참조조문·참조판례 |
| 해석 | 헌재결정례 | `detc` | 3.4 질의 | 메타 + 결정요지·참조조문 |
| 해석 | **법령해석례** | **`expc`** | 3.4 질의 | 메타 + 질의요지·회답·참조조문 |
| 해석 | **중앙부처 1차 해석** | `{부처}CgmExpc` ⚠️ | 부처별 × 3.4 질의 | 메타 + 질의·회답 요지 |
| 해석 | **중앙행정기관 결정선례** | ⚠️ 미확인 | — | P0 실측에서 결정 |
| 해석 | 행정심판례 | `decc` | 3.4 질의 | 메타 + 재결요지 |
| 연계 | 법령–자치법규 연계 | `lnkOrd` 등 | 조직법·혈액관리법 | 교차확인용 |

> 응답 필드명(예: 판례의 `사건명`·`사건번호`·`선고일자`·`법원명`·`판례상세링크`, 해석례의 `안건명`·`안건번호`·`회신일자`)은 **P0 실측으로 확정**하고 `docs/api-probe.md`에 기록한다.

### 4.2 판례·해석 요지만 저장하는 이유
- 판결문 전문은 길고(건당 수천~수만 자) 비식별 처리 이슈가 있어, **판시사항·요지·참조조문까지만 저장**하고 전문은 원문 링크로 보낸다.
- 데이터 JSON 크기 예산을 지키기 위해 요지는 600자에서 자르고 "원문에서 계속 ↗"을 붙인다.

### 4.3 알려진 운영 이슈 (반드시 반영)
| 이슈 | 대응 |
|------|------|
| `Referer` 헤더 없으면 유효한 OC에도 "사용자 정보 검증 실패" | `Referer: https://www.law.go.kr/` 고정 주입 |
| Node 기본 User-Agent를 봇으로 분류 | 일반 브라우저 UA 지정 |
| 클라우드 IP에서 안티봇 JS 리다이렉트 페이지 반환 | **런타임 API 호출 금지(v1)**, 빌드타임 수집 후 정적 JSON 배포. CI 실패 시 담당자 PC 수집 경로 |
| 간헐적 200 + 빈 본문/HTML 점검 페이지 | 루트 태그 검증 → 지수 백오프 재시도(3회) → 실패 시 이전 스냅샷 유지. **빈 결과를 "자료 없음"으로 확정하지 않음** |
| 목록 1페이지 최대 100건 | `page` 루프 + `totalCnt` 대조 |
| 판례 짧은 검색어 → 무관 결과 다수 | 관련성 점수 + 검수 (3.4) |
| 호출량 증가(유형 × 질의 × 페이지) | 요청 간 300ms 지연, 동시성 2, 본문 조회는 **신규·변경 건만**(증분 수집) |
| OC 키 노출 | `.env`/GitHub Secrets만 사용, 로그·산출물에서 `OC=***` 마스킹 |

### 4.4 증분 수집
- `data/state.json`에 유형별 마지막 수집일과 ID→해시 맵을 저장.
- 목록은 매주 전체 재조회(가벼움), **본문은 신규 ID 또는 메타(시행일·선고일 등) 변경 건만** 재조회.
- 직전 스냅샷과 비교해 `changes.json`(추가/개정/폐지/신규 판례·해석) 생성.

### 4.5 원문 링크 규칙
| 대상 | 링크 | 비고 |
|------|------|------|

## 6. 데이터 모델

```ts
// src/types/model.ts
export type NormSource = 'law' | 'eflaw' | 'admrul' | 'ordin' | 'trty' | 'pi';
export type CaseSource = 'prec' | 'detc' | 'expc' | 'cgm' | 'pre' | 'decc';

export type Level =
  | 'L0_CONSTITUTION' | 'L0_TREATY'
  | 'L1_ACT' | 'L2_DECREE' | 'L1R_RELATED' | 'L1A_ADMRULE'
  | 'LO_ORDINANCE' | 'LO_ORD_RULE'          // 조례 / 자치 규칙
  | 'L3_ARTICLES' | 'L4_REGULATION' | 'L5_RULE' | 'L6_GUIDELINE';

export type FieldCode =
  'ORG'|'HR'|'PAY'|'FIN'|'AUD'|'BLD'|'MED'|'DIS'|'VOL'|'INT'|'INF'|'ETC';

/** 규범 축 */
export interface NormItem {
  id: string;                 // `${source}:${원천ID}`
  source: NormSource;
  sourceId: string;
  title: string;
  shortTitle?: string;
  kind: string;               // 법률/대통령령/조례/규칙/정관/규정/시행규칙 …
  level: Level;
  primaryField: FieldCode;
  secondaryFields: FieldCode[];
  parentId: string | null;
  agency: string;             // 소관부처 / 지자체명 / 기관명
  region?: { sido: string; sigungu?: string; code?: string }; // 자치법규만
  promulgatedAt?: string;
  effectiveAt?: string;
  revisionType?: string;
  upcoming?: { effectiveAt: string };
  articles?: { no: string; title: string }[];  // 핵심 법령의 조문 목차(조문 단위 연결용)
  url: string;
  isCore: boolean;
  caseCount: number;          // 연결된 노출 판례·해석 수 (나무 배지)
  flags: ('RECENT'|'UPCOMING'|'NO_PARENT'|'LINK_BROKEN')[];
}

/** 해석·적용 축 */
export interface CaseItem {
  id: string;                 // `${source}:${원천ID}`
  source: CaseSource;
  sourceId: string;
  docNo: string;              // 사건번호 / 안건번호 / 재결번호
  title: string;              // 사건명 / 안건명
  issuer: string;             // 법원명 / 헌법재판소 / 법제처 / ○○부 / 행정심판위원회
  decidedAt: string;          // 선고·결정·회신·재결일
  outcome?: string;           // 판결유형·주문 요지(있을 때)
  summary?: string;           // 판시사항·요지 (≤600자)
  citedLaws: { lawName: string; article?: string; normId?: string }[];
  fields: FieldCode[];
  issueTags: string[];        // 쟁점 태그(검수 시 부여): 예) "헌혈자 개인정보", "회비 성격"
  relevance: number;          // 0–100
  review: 'auto' | 'candidate' | 'approved' | 'rejected';
  url: string;
}

/** 축 간 연결 */
export interface Relation {
  from: string;               // CaseItem.id
  to: string;                 // NormItem.id
  article?: string;           // "제8조" (조문 단위 연결)
  type: 'CITES' | 'ABOUT';    // 참조조문 자동 / 담당자 지정
}

export interface DatasetMeta {
  baseDate: string;
  generatedAt: string;
  counts: {
    norms: Record<NormSource, number> & { total: number };
    cases: Record<CaseSource, number> & { total: number; candidate: number };
  };
  apiTotalCnt: { pi: number };
  brokenLinks: number;
}
```


- "적십자 지원 조례가 **없는** 시·도" 보기 토글(0건 타일 강조) — 지역 간 비교용.

### 7.5 판례·해석 라이브러리 (/cases)
```
┌──────────────────────────────────────────────────────────────────────┐
│ [전체 M] [판례] [헌재] [법령해석례] [중앙부처 1차 해석] [결정선례] [행정심판] │
│ 필터: 분야 ▾  연도 ▾ (2000–2026 슬라이더)  관련 규범 ▾  쟁점태그 ▾  ☐자동분류 포함 │
│ 정렬: 최신순 | 관련도순                                                  │
├──────────────────────────────────────────────────────────────────────┤
│ ⚖ 판례  대법원 2019다○○○○○  2021. 3. 11.                    관련도 ●●●○ │
│   손해배상(기)  · 혈액사업 · #헌혈자 개인정보                             │
│   판시사항: …(2줄 요약)…                                                │
│   관련 규범: 혈액관리법 제12조 · 대한적십자사 조직법 제8조                  │
│   [원문 ↗]  [관련 규범 보기]  [링크 복사]                                 │
├──────────────────────────────────────────────────────────────────────┤
│ 📘 법령해석례  법제처 2X-0XXX  2023. 6. 2.   질의기관: 보건복지부          │
│ …                                                                     │
├──────────────────────────────────────────────────────────────────────┤
│ 🔎 law.go.kr에서 '대한적십자사'로 더 찾기 ↗  (검수되지 않은 자료 포함)      │
└──────────────────────────────────────────────────────────────────────┘
```
- 카드 공통 필드: 유형 아이콘 · 문서번호 · 일자 · 발행기관 · 제목 · 분야/쟁점 칩 · 요지 2줄 · 관련 규범(조문 단위 링크) · 원문.
- **자동분류(`auto`) 항목에는 "자동분류" 표시**, 기본 필터는 `approved + auto`. 검수 대기(`candidate`)는 노출하지 않음.
- 상단에 **연도별 막대(타임라인)** 미니차트 — 막대 클릭 시 연도 필터.
- 모든 화면 하단 고지: "요지는 원문 일부를 발췌한 것이며, 판례 변경 여부 등은 원문에서 확인하세요."

### 7.6 "law.go.kr에서 더 찾기" 와 실시간 검색(v2)
- **v1**: 정적 데이터 + 유형별 law.go.kr 검색 딥링크. 검수 범위 밖 자료는 공식 사이트에서 찾도록 안내.
- **v2(선택)**: Vercel Serverless(서울 리전 `icn1`) 프록시로 `lawSearch.do` 실시간 조회.
  - 조건: P0에서 **Vercel 리전 IP로 API 호출 성공을 실측**한 경우에만 착수.
  - 결과는 "실시간·미검수" 라벨로 구분, 15분 캐시, 분당 요청 제한, OC는 서버 환경변수.

### 7.9 검색 (⌘K)
- 한 번에 두 축을 검색. 결과 그룹: **법령 / 기관규정 / 조례 / 판례·해석 / 분야**.

- 단계마다 **Plan 모드**로 계획을 먼저 받고 승인 후 구현.

## 부록 A. API 요청 예시

```bash
H=(-H "Referer: https://www.law.go.kr/" -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126 Safari/537.36")
BASE="https://www.law.go.kr/DRF"

# 공공기관 규정 — 대한적십자사
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=pi&type=XML&query=대한적십자사&display=100&page=1" "${H[@]}"

# 자치법규 — 자치법규명에 '적십자'
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=ordin&type=XML&query=적십자&display=100" "${H[@]}"

# 판례 — 본문검색(search=2) '대한적십자사'
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=prec&type=XML&search=2&query=대한적십자사&display=100" "${H[@]}"

# 판례 본문(요지·참조조문 추출용)
curl -sS "$BASE/lawService.do?OC=$LAW_OC&target=prec&type=JSON&ID={판례일련번호}" "${H[@]}"

# 법령해석례
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=expc&type=XML&query=대한적십자사&display=100" "${H[@]}"

# 헌재결정례 / 행정심판례
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=detc&type=XML&query=적십자&display=100" "${H[@]}"
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target=decc&type=XML&query=대한적십자사&display=100" "${H[@]}"

# 중앙부처 1차 해석 — target명은 P0에서 가이드 확인 후 확정 (예시 형식)
curl -sS "$BASE/lawSearch.do?OC=$LAW_OC&target={부처약어}CgmExpc&type=XML&query=혈액&display=100" "${H[@]}"
```

## 부록 B. 검수 가이드 요약 (`docs/review-guide.md` 초안)
1. **승인(approved)**: 대한적십자사가 당사자·질의기관이거나, 조직법·정관·기관규정의 해석이 쟁점이거나, 혈액·헌혈·구호 사업 수행과 직접 관련된 판단.
2. **제외(rejected)**: 기관명이 사실관계에 지나가듯 등장할 뿐 쟁점과 무관(예: 경력 기재, 기부처 언급).
3. **쟁점태그**: 2~4어절 명사구로 통일(예: `헌혈자 개인정보`, `적십자회비 법적 성격`, `혈액원 근로자 해고`). 신규 태그는 taxonomy.yaml에 등록.
4. **연결 규범 지정**: 참조조문 자동 연결이 없거나 틀렸으면 `about`에 `normId#제n조` 형식으로 지정.
